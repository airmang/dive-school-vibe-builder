# 8단계 실행과 완료 기준

## 공통

새 프로젝트는 현재 지원되는 Node.js LTS와 Next.js 요구 사항을 공식 문서로 확인한다.
이 패키지는 실행 가능한 Next.js 앱 템플릿이 아니라 앱을 만드는 절차다.
처음부터 React/SSR 개념 강의를 하지 않는다. 사용자에게는 화면·데이터·로그인·공개의 역할만 설명한다.
운영·보안 판단은 숨기지 않는다. GitHub, Supabase, Vercel 계정·비용·학교 허용 범위는 사람이 확인한다.

## 1. 화면

기존 프로젝트가 있으면 수정한다. 없으면 최소 Next.js + TypeScript를 구성한다.
앱 코드는 앱 저장소 루트에 둔다. 설치된 `.agents/skills` 안이나 하네스 배포 저장소에 앱을 만들지 않는다.
루트에 이미 AGENTS/PROJECT/PLAN이 있으므로 `create-next-app .`이 충돌하면 덮어쓰거나 지우지 않는다.
필요 시 별도 임시 scaffold 폴더에 생성한 뒤 충돌 없는 앱 파일만 검토·복사하고 임시 폴더를 정리한다.
가상 데이터 3~5건, 입력폼·목록·수정/삭제, 기본 모바일 대응을 만든다.
처음에는 메모리 상태여도 된다. 그 상태가 공유·영구 저장이 아님을 화면/설명에 명확히 표시한다.
불필요한 ORM, 결제, 알림, 복잡한 달력 라이브러리를 추가하지 않는다.

## 2. 로컬

현재 package.json에서 실제 실행 명령을 확인한다. 정상 URL을 보여주고 교사의 화면 확인을 받는다.
빈 입력, 너무 긴 입력, 날짜 없는 입력, 삭제 취소, 저장 실패, 좁은 화면을 확인한다.
도구가 브라우저를 볼 수 없으면 사용자에게 확인 동작을 설명하고 `MANUAL-PASS`로 남긴다.
빌드 통과를 브라우저 확인과 혼동하지 않는다. 테스트 명령이 없으면 없다고 쓰고 필요한 작은 테스트를 추가한다.

## 3. 테이블

프로젝트 소유권/테스트 환경/리전을 사람이 결정한다. 현재 서비스 설정을 추측해서 만들지 않는다.
`supabase/migrations/`에 재현 가능한 SQL을 작성한다. 생성·RLS 활성화·최소 grants를 같은 변경으로 묶는다.
필수값·외래키·유형 제약을 정하고 teacher/student 매핑을 사용자 편집 가능한 프로필과 분리한다.
SQL 파일을 만든 것은 DB 적용 완료가 아니다. 실행 권한이 없으면 SQL Editor 수동 경로를 안내한다.
운영 DB가 아닌 테스트 DB에 가상 데이터만 넣고 적용 내역을 기록한다.

## 4. 연결

Supabase URL과 publishable key의 **입력 위치**를 안내한다. 키 값을 채팅으로 받지 않는다.
SDK 클라이언트를 최소하게 구성하고 필요하면 공식 SSR 예제를 해당 Next.js 버전에 맞춘다.
RLS가 막는다고 정책을 전부 공개로 바꾸지 않는다. 5단계의 최소 테스트 로그인을 먼저 만들 수 있다.
미리보기용 관리자 SQL 입력과 일반 사용자 앱 쓰기는 구분한다. 전자가 성공해도 후자를 검증한 것이 아니다.
브라우저 새로고침·다른 세션의 조회·실패 시 에러 표시를 확인한다. 권한 실패 시 가짜 성공을 표시하지 않는다.

## 5. 로그인·권한

Google OAuth를 기본 후보로 삼되 학교 계정의 실제 사용 가능 여부를 확인한다.
연수에서는 미리 만든 테스트 계정으로도 검증할 수 있다. 가입 링크/메일 발송 제한 때문에 멈추지 않도록 강사가 사전 확인한다.
학교 도메인이나 OAuth `hd` 표시만을 권한 근거로 쓰지 않는다. 승인된 구성원 ID·역할을 DB/서버에서 확인한다.
DB 정책을 일반 사용자 세션으로 테스트한다. 성공 요청뿐 아니라 타인 row 조회/수정/삭제 거부도 확인한다.
RLS 거부가 빈 결과/0건 변경으로 나타날 수 있으므로 HTTP 성공 코드만 보고 통과 처리하지 않는다.
원래 데이터가 존재하고 바뀌지 않았다는 점을 소유자 계정으로 재확인한다.

## 6. GitHub

초기부터 로컬 Git 체크포인트를 만들 수 있다. 원격 push 전에는 대상·범위·연결된 자동 배포를 확인한다.
앱 저장소는 private을 기본 후보로 한다. 공개하더라도 코드 공개와 데이터 공개는 별개로 검토한다.
`.gitignore`는 이미 추적 중인 파일이나 과거 커밋을 지우지 않는다. 커밋 후보·추적 파일·필요한 이력을 검토한다.
실제 학생 데이터, 계정 이메일, 토큰을 README·테스트·스크린샷에도 넣지 않는다.
사용자의 구체적인 push 승인 후 실행한다. remote URL을 꾸며내지 않는다.

## 7. Vercel

GitHub 연결, 프로젝트 루트, 빌드 명령, 환경별 값을 확인한다. Root Directory는 앱의 package.json 위치다.
Preview는 테스트 데이터 환경에 연결한다. 신뢰하지 않는 PR 배포가 운영 비밀/운영 DB에 접근하지 않게 한다.
OAuth에는 Google→Supabase 콜백과 Supabase→앱 리다이렉트가 있어 두 경로를 구분해 설정한다.
운영용 허용 URL은 구체적으로 등록한다. 편의를 위한 광범위한 와일드카드를 기본으로 하지 않는다.
환경변수를 바꾼 뒤에는 새 배포가 필요한지 확인한다. 로컬에서만 작동하는 localhost 리다이렉트를 남기지 않는다.
실제 배포 성공과 URL 접속을 확인하고 PLAN에 주소·검증 시각을 기록한다.

## 8. 공유

먼저 교사/학생 테스트 계정과 비로그인으로 배포 URL을 검증한다. 익명 공개 범위도 실제 확인한다.
휴대폰·새 브라우저에서 사용해 본다. 로컬 테스트만으로 공유 준비가 끝났다고 하지 않는다.
운영 담당, 학교 검토, 보관/삭제, 백업/복구, 서비스 한도·요금·중단 대응을 확인한다.
가상 데이터 파일럿이라면 실데이터 승인을 받은 것처럼 적지 않는다. 공유 범위와 데이터 모드를 명시한다.
`check --gate release` 후 사람이 공유를 승인하고 URL을 전달한다. 실제 전달하지 않았으면 S8.4는 미완료다.
