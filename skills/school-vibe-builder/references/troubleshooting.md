# 막혔을 때: 하나씩 원인을 좁히기

| 증상 | 확인 순서 | 피할 행동 |
|---|---|---|
| 스킬이 안 보임 | 현재 앱 루트, `.agents/skills/school-vibe-builder/SKILL.md`, `/skills`, 다음 턴/재시작 | 전체 환경 재설치부터 시작 |
| 계획 파일이 또 생성됨 | 현재 폴더와 기존 PROJECT/PLAN 확인, 이어하기 모드로 전환 | 기존 계획 덮어쓰기 |
| create-next-app이 파일 충돌 | 문서 보존, 임시 scaffold에서 앱 파일만 검토 복사 | AGENTS/PLAN 삭제 |
| localhost 접속 불가 | 실제 서버 프로세스, 실행 로그, 포트, 올바른 URL | 서버가 실행됐다고 추측 |
| 새로고침하면 데이터 사라짐 | 메모리 mock인지 실제 DB 쓰기인지 확인 | localStorage를 공유 DB로 설명 |
| Supabase 401/403/빈 결과 | 프로젝트 URL/키 종류/사용자 세션/grants/RLS 순서 | service-role 키를 프런트에 넣기 |
| 교사도 자기 자료 수정 불가 | 담당자 매핑, SELECT와 UPDATE 정책, 소유자 조건 | RLS 해제 |
| 다른 학생 자료가 보임 | 공유 일시 보류, API/RLS/역할/캐시 검증 | 화면 필터만 추가 |
| Google 로그인 차단 | 학교 계정 정책, OAuth 설정, 리다이렉트, 승인 구성원 | 이메일 도메인만 확인하고 모두 허용 |
| 로그인 메일이 안 옴 | 메일/발송 제한·SMTP·사전 테스트 계정 확인 | 수십 번 재발송 |
| Vercel에서만 로그인 실패 | 실제 URL, 환경별 값, Supabase allow-list, 새 배포 | 무제한 redirect 와일드카드 |
| .env가 GitHub에 올라감 | 공유/배포 중지 검토, 키 폐기·재발급, 추적/이력 점검 | .gitignore만 추가하고 종료 |
| check 통과인데 앱 오류 | check는 문서/정적 검사임, 실제 빌드·브라우저·DB 재현 | 도우미 결과를 보안 인증으로 해석 |

## 막힌 작업의 기록

PLAN의 작업 상태를 `[!]`로 두고 증상, 재현, 마지막 확인, 다음 한 행동, 담당자를 적는다.
서비스 연결이 없으면 SQL/코드/가상 데이터로 가능한 로컬 작업을 진행한다. 외부 실행은 미완료로 남긴다.
이후 사용자가 실제 성공을 확인하면 `MANUAL-PASS` 근거로 갱신한다.

## 복구 프롬프트

```text
$school-vibe-builder로 현재 문제를 정리해줘.
PLAN의 마지막 성공 단계와 지금 실패한 단계만 비교하고,
한 번에 원인 하나를 확인해줘. 권한을 풀거나 프로젝트를 다시 만들지는 마.
```

```text
$school-vibe-builder로 다시 이어가자.
체크박스와 실제 파일 상태가 다르면 실제 상태를 우선하고,
왜 다른지 기록한 뒤 다음 작업을 정해줘.
```
