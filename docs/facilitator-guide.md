# 강사용 운영 안내

## 사전 준비

참여자 노트북에서 Codex 로컬 작업, Node.js, Git, 계정 로그인과 학교망 접근을 먼저 확인한다.
이 하네스는 교사가 개발하는 연수용이다. 학생에게 Codex 계정을 만들게 하는 과정이 아니다.
Supabase·GitHub·Vercel은 각 교사가 소유할 계정을 쓰고, 강사의 관리자 키나 계정을 공동 사용하지 않는다.
학교 Google OAuth가 가능한지, 테스트 계정/메일 발송 경로가 작동하는지 강사 노트북으로 선행 확인한다.
학교 계정 정책을 피하려고 비승인 계정으로 실데이터를 옮기지 않는다.
현재 서비스 약관·플랜·학교 외부 서비스 이용 절차를 확인한다. 무료 사용을 영구 운영 보장으로 설명하지 않는다.

연수에서 쓰는 데이터는 가상 학생 A/B, 가상 대학, 가상 상담 내용으로 미리 정한다.
설치 파일은 ZIP을 풀어 배포하고 프로젝트별 설치 하나로 통일한다.
참가자에게는 `START_HERE.md`만 먼저 읽히고 전체 스킬 구조를 외우게 하지 않는다.

## 함께 완주할 공통 예제

먼저 공통 학급 일정 앱으로 화면·로컬 실행·DB·배포를 경험한다.
그 뒤 각 교사의 상담카드/대입 일정으로 변형한다. 학생별 정보 앱은 권한 검증 시간이 추가로 필요하다.
MVP는 3~5개 기능으로 제한한다. QR 디자인·알림·채팅·AI 분석은 첫 결과물에 넣지 않는다.

## 시연할 핵심 대화

1. “학급 일정 앱을 만들고 싶어. Grill me.” → 바로 코딩하지 않는 것을 보여준다.
2. “교사만 입력, 학생은 조회야.” → 입력/읽기 주체를 구분한다.
3. “공통 일정만 공개할게. 개인별 정보는 없어.” → 공개 범위 결정을 보여준다.
4. “계획대로 시작해.” → PROJECT와 PLAN을 실제 파일로 확인한다.
5. “일단 여기까지 저장하고 새 세션에서 계속하자.” → 대화가 아니라 파일로 작업이 이어지는 것을 보여준다.
6. “학생도 수정할 수 있게 됐네?” → 버튼 숨기기가 아니라 DB/API 권한을 시험하게 한다.

## 참가자가 놓치기 쉬운 판단

계획은 장식 문서가 아니다. 자신이 설명한 업무와 권한이 맞는지 읽어야 한다.
작동 화면만으로 공유를 승인하지 않는다. 학생 A/B/비구성원을 실제로 바꿔 시험한다.
AI가 보여준 명령 성공 메시지를 곧바로 믿지 말고 실제 URL·DB 반영·다른 세션 결과를 확인한다.
실제 수행하지 않은 수동 작업은 대기 상태로 남기는 것이 정상이다.

## 클라우드 연결이 막히면

화면/로컬 코드/SQL 파일/계획 작성까지 진행하고 해당 외부 단계만 차단으로 남긴다.
API 키·관리자 계정 공유, RLS 해제, 승인 절차 해제로 해결하지 않는다.
연수 종료 산출물에 '가상 데이터 로컬 시연', '배포 테스트 미완료' 등 실제 상태를 명시한다.

## 수업 결과 확인

완성도는 UI 화려함보다 업무 적합성, 올바른 저장, 역할별 차단, 재개 가능한 계획으로 확인한다.
결과 보고에는 앱 목적, 가상 데이터 화면, 역할별 테스트 요약, 실제 배포 여부, 남은 과제만 넣는다.
학생 실명·입시 정보·상담 원문을 연수 산출물로 제출시키지 않는다.

모델 행동 리허설에는 [12개 확인 시나리오](skill-evaluation-cases.md)를 사용한다. 이 평가는 로컬 도우미 자동 테스트와 별도다.
