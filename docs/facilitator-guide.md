# 다른 학교에서 교사 연수로 사용하기

목표: 참가자가 자기 업무를 설명하고, 실제 웹앱을 만들고, 실행·검증·배포의 다음 행동을 스스로 이어가게 한다.
하네스는 수업 평가 도구가 아니라 개인 개발 도우미다. 진행 속도를 일률적으로 맞추려고 완료를 허위 표시하지 않는다.

## 사전 준비

참가자별 노트북에서 Codex 로그인, Node.js/Git 설치, 학교망에서 필요한 서비스 접근을 확인한다.
웹앱 배포에는 각자의 GitHub·Vercel 계정, 서버 저장이 필요한 경우 Supabase 계정을 준비한다.
계정/메일 인증은 강의 시작 전에 리허설한다. 학교 계정 OAuth 제한, 프록시/방화벽, 무료 플랜 제한은 실제 환경에서 확인한다.
강사는 고정된 릴리스/커밋 버전의 ZIP을 배포하고 설치 명령을 실행해 본다. 실제 학생 데이터·공용 관리자 키를 배포하지 않는다.

## 당일 출발점

하네스 폴더에서 `node scripts/install.mjs --project "../my-project"`로 묶음 설치한다.
참가자는 my-project를 열고 `$dive-webapp으로 공유 웹앱 모드를 시작해줘. [내 업무]를 만들고 싶어.`라고 말한다.
기술 선택 시험을 하지 않는다. 공통 하네스가 사용 방식과 최소 범위를 질문하고, 웹앱 스킬이 연결·배포를 안내한다.

## 진행

가상 데이터 첫 화면→로컬 확인까지 같이 진행하고, 이후 필요한 저장·로그인·배포로 넘어간다.
서버 저장이 불필요한 도구는 이유를 기록하고 Supabase 단계를 제외한다. 필요한 앱은 RLS/권한을 생략하지 않는다.
한 참가자가 인증/망 문제로 막히면 그 단계는 차단으로 두고 샘플 데이터의 로컬 검증을 진행한다.
서버가 연결되지 않았는데 “배포 성공”으로 표시하거나 전체 계정을 강사의 관리자 키로 우회하지 않는다.

## 마무리

각자 실제 확인된 기능, 미확인 사항, 실행 방법, 다음 행동을 PLAN에 남긴다.
실제 URL 공유는 승인된 범위에서만 진행한다. 정식 업무 사용은 권한 검증·운영 책임·조직 데이터 절차를 별도 확인한다.
연수 후에는 같은 하네스로 게임·자동화·파일 처리 등을 만들 수 있다. 새 프로젝트에서는 dive-builder로 시작하면 된다.
