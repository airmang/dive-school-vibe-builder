# 0.2 설계 결정

## 목적

비개발자가 실제 개발 과정에서 길을 잃지 않도록 돕는다. 교육·평가를 제품의 필수 기능으로 삼지 않는다.
DIVE의 목표 구체화→계획→실행→변경 확인→검증→재개 원리를 참고하되 데스크톱 런타임은 복제하지 않는다.

## 분리

공통 dive-builder는 모든 형태의 프로젝트를 지원하는 절차다. 스택·단계·프로젝트 종류를 제한하지 않는다.
dive-webapp은 선택형 공유 웹앱의 Next.js/Supabase/GitHub/Vercel 경로다. 외부 연수에서 표준으로 사용한다.
분류는 계획을 돕는 힌트이지 기능을 금지하는 조건이 아니다.

## 조합 계약

같은 Codex가 필요한 SKILL.md를 추가로 읽는다. 독립 프로세스, 호출 API, 에이전트 간 메시지 시스템은 없다.
스킬 경로를 발견해 읽었을 때만 사용했다고 한다. 기본 설치는 같은 상위 폴더에 공통+웹앱을 배치한다.
웹앱이 없으면 공통은 단독 동작한다. 웹앱 요청은 추가 설치 안내로 명확히 중단한다.
AGENTS/PROJECT/PLAN은 하나씩만 유지한다. 모드 전환·기능 변경은 기존 문서를 갱신한다.

## 점검 계약

PLAN의 DIVE_MODE와 데이터/인증 필요, 합의 상태만 최소 메타데이터로 사용한다. 별도 JSON 상태는 없다.
general은 임의의 작업 ID/단계를 허용한다. webapp에만 누락 점검용 ID 집합을 적용한다.
적용 제외는 N/A 근거와 별도로 집계하며, 데이터/인증 필요에 따라 제외 가능한 항목을 좁힌다.
완료는 마지막 기록의 PASS/MANUAL-PASS를 요구한다. 뒤에 FAIL이 있으면 오래된 PASS로 통과시키지 않는다.
기록은 사람이 편집 가능하다. 승인 위조 방지, 코드와 증거의 자동 결합, 실제 테스트 실행기가 아니다.

## 호환성과 비목표

이전 이름은 명시적 별칭과 CLI 경로로 보존한다. 기존 앱 문서를 자동 덮어쓰지 않는다.
구 0.1 계획은 읽기 전용 상태 조회가 가능하고 새 점검에는 명시적 이관이 필요하다.
플러그인 마켓 배포, 자동 클라우드 설정, 실제 앱 템플릿 번들, 새로운 데스크톱 UI는 이번 변경 범위가 아니다.
