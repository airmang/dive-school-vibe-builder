# 검증 결과와 범위

작성일: **2026-09-16** · 패키지: **School Vibe Builder 0.1.0**

## 실제 실행한 검증

| 항목 | 실행 환경 / 결과 |
|---|---|
| Node 도우미 구문·동작 | Linux, Node.js v22.16.0 |
| 자동 테스트 | **45개 통과, 실패 0, 건너뜀 0** |
| 스킬 구조 | SKILL.md front matter, 폴더명, UI 메타데이터 확인 |
| 템플릿 | 4개 프로필 생성, 한글·공백 경로, 미치환 항목 없음 |
| 진행 계획 | 필수 작업 ID 29개와 PLAN 템플릿 일치 |
| 문서 | 내부 상대 링크, 코드 블록, UTF-8 기본 검사 통과 |

실행 명령은 저장소 루트에서 다음과 같다. 의존성 설치가 필요 없다.

```text
npm test
npm run verify
```

자동 테스트 원문은 [test-output.tap](test-output.tap)에 보관했다.

## 자동 테스트가 확인한 내용

초안 생성과 dry-run, 기존 PROJECT/PLAN 재생성 차단, 기존 AGENTS/ignore 보존,
제안 파일 충돌 시 부분 생성 방지, 심볼릭 링크 경로 거부, 배포 저장소와 앱 폴더 구분을 시험했다.

상태 조회, 읽기 전용 점검, 완료 근거 누락/잘못된 시각/임시 문구, 필수 작업 삭제/중복,
prepush/release의 선행 작업 검사를 시험했다. 공유 직전 점검이 이미 공유했을 것을 요구하는 순환도 피했다.

실제 로컬 Git 저장소를 만들어 ignore 효과, 이미 추적된 .env/학생 데이터 경로 탐지를 시험했다.
비밀 패턴 발견 시 파일·줄·유형만 보여주고 값은 출력하지 않음을 확인했다.
실제 .env 내용을 열지 않으며 공개용 키와 일부 관리자 키 패턴을 구분하는지 시험했다.

설치된 스킬 폴더의 독립 실행기로 새 프로젝트 문서를 실제 생성했다.
사용자 범위 설치는 가짜 홈 폴더에서 시험했으며 기존 Codex 설정을 유지함을 확인했다.
CLI JSON 출력과 실패 종료 코드도 확인했다.

## 확인하지 않은 내용

**실제 Codex 세션에서의 모델 행동, Windows/macOS 실제 기기 실행, 학교망, Google OAuth,
Supabase RLS의 실제 클라우드 실행, GitHub 업로드, Vercel 배포, 학생 계정 접속은 검증하지 않았다.**

이 패키지는 완성 앱이 아니므로 특정 캘린더/상담 앱의 기능·보안 테스트 결과도 아니다.
자동 테스트의 PASS 근거 행은 파서를 시험하기 위한 **합성 입력**이지 실제 서비스 통과 기록이 아니다.
모델 행동 리허설은 [skill-evaluation-cases.md](skill-evaluation-cases.md)로 별도 진행한다.

## 운영 적용 전에

강사는 자신의 노트북에서 새 앱 폴더 설치 → 인터뷰 → 계획 생성 → 중단/재개를 먼저 확인한다.
그 뒤 가상 데이터와 역할별 테스트 계정으로 실제 DB/API 허용·차단과 배포 로그인 왕복을 확인한다.
학교에서 실제 학생 데이터를 사용할 수 있는지는 별도 검토한다.
