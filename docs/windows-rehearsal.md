# Windows 설치부터 웹앱까지 리허설

실제 Windows 노트북에서 실행한 결과를 남긴다. macOS 자동 테스트·PowerShell 문법 확인은 이 리허설의 통과가 아니다.
처음 두 사례는 Node.js/Git이 없는 별도 테스트 기기/VM을 권한다. 기존 업무 노트북의 설치를 지워 시험하지 않는다.

| 사례 | 실제 확인할 결과 |
|---|---|
| Node/Git 없음, WinGet 있음 | 앱 작업 폴더에서 GitHub 링크+설치 요청 → OS 기본 도구로 배포물 다운로드/압축 해제 → 필요한 두 패키지 설치 지원 → node/npm.cmd/git 버전 확인 → 처음 앱 폴더에 스킬 설치 |
| WinGet 없음/학교망 차단 | 공식 설치 파일 경로와 필요한 사람 조작 안내. WinGet 의무 설치·망/보안 해제 없이 진행 또는 정확한 차단 기록 |
| 호환 Node/Git 이미 있음 | 불필요한 재설치·업그레이드 없이 현재 경로·버전 확인 후 진행 |
| Node 20.8 또는 그 이전 | 설치 도구 호환과 기본 웹앱 요구사항을 구분, 필요한 버전 준비 지원 |
| 설치 후 Codex에서 명령 못 찾음 | 설치 경로·현재 PATH 확인, 필요한 재시작 → 새 프로세스에서도 실제 명령 성공 |
| PowerShell npm.ps1 실행 차단 | npm.cmd/npx.cmd 실행으로 진행, 실행 정책 변경 안 함 |
| 관리자 인증을 할 수 없음 | 설치 성공으로 표시하지 않고 학교 담당자의 설치 경로와 재개 방법 안내 |
| 한글·공백 있는 앱 경로 | 스킬 3개 설치·인식, 문서 초안/도우미 실행 성공 |
| 스킬·계획 파일이 있는 앱 폴더 | 빈 임시 scaffold → 기존 AGENTS/PROJECT/PLAN/.env/스킬 보존 → 앱 폴더에서 의존성 설치·실행·빌드 |
| 설치 후 새 Codex 대화 | $dive-webapp 호출, 공통+웹앱 지침 적용. 설치 인터뷰 반복 없이 앱의 필요한 기획 질문 |
| 오늘 중단 후 다음날 | 기록·실제 파일 대조, 서버 실행 여부 재확인 후 이어서 작업 |

첫 앱은 가상 데이터의 DB 없는 계산기/모둠 편성 등으로 로컬 동작을 확인한다.
로그인·서버 저장이 필요한 앱은 별도로 Supabase 테스트 계정/RLS 허용·거부 → GitHub 대상 확인 → Vercel 실제 URL까지 시험한다.
로컬 화면 성공과 클라우드 검증을 같은 완료로 기록하지 않는다.

## 결과 기록

비밀키/계정 토큰/학생 자료를 붙여넣지 않는다. 설치된 도구 버전과 경로만 기록한다.

```text
시험 시각·Windows 버전·CPU:
Codex 버전·현재 셸(Windows PowerShell/PowerShell/WSL):
배포물 버전·커밋:
시험 전 node/npm/git/winget 유무:
시작 요청:
실행한 설치 방법·종료 결과:
설치 후 현재 셸의 node/npm.cmd/git 경로·버전:
Codex 재시작 후 같은 명령 결과:
앱 폴더·스킬 인식:
로컬 실행·빌드·브라우저 결과:
실패 문구·다음 조치:
Supabase/Vercel 시험 여부와 실제 확인 범위:
```
